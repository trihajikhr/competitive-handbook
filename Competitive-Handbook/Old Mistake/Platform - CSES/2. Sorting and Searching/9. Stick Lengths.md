# Stick Lengths

## Problem
Ada $n$ buah kayu dengan berbagai panjang. Tugasmu adalah memodifikasi kayu-kayu tersebut sehingga setiap kayu memiliki panjang yang sama.

Kamu bisa memperpanjang atau memperpendek setiap kayu. Kedua operasi tersebut membiayai $x$, di mana $x$ adalah selisih antara panjang baru dan panjang asli.

Berapa total biaya minimumnya?

## Solution
Urutkan array, lalu ambil nilai median atau index di posisi tengah berupa $n/2$. Nilai tengah ini akan menjadi titik acuan perubahan semua elemen array. 

Jika arraynya diwakili oleh $a$, , dan banyaknya data diwakili olen $n$, maka jawaban bisa didapatkan dengan formula berikut:

$$\sum_{i=1}^{n} \left| a \lfloor n/2 \rfloor - a[i] \right|$$
## Proof of Correctness

> [!TIP]
> Kenapa memilih nilai median pasti paling murah?

Kuncinya ada di jumlah data di kiri dan kanan. Katakanlah kita memiliki $target$ yang menjadi titik acuan dimana semua data akan memanjang atau memendek untuk menyamakan dengan nilai $target$, yang mana $target$ berupa posisi index tengah array.

* Setiap kali kita menggeser titik $target$ sejauh $1$ langkah, misal ke kanan:
	* Semua lidi yang ada di sebelah kiri titik itu akan menderita (jaraknya bertambah).
	* Semua lidi yang ada di sebelah kanan titik itu akan diuntungkan (jaraknya berkurang).
* Selama jumlah lidi di sebelah kiri lebih banyak daripada di sebelah kanan, menggeser titik ke kanan itu rugi (karena yang menderita lebih banyak daripada yang diuntungkan).
* Sebaliknya, kalau jumlah lidi di sebelah kanan lebih banyak, menggeser titik ke kiri itu rugi.

*Nah*, titik di mana benturan kepentingan ini seimbang persis adalah saat jumlah lidi di kiri dan kanan sama banyak. Titik tengah inilah yang kita sebut sebagai median. Jika kita geser ke kiri atau ke kanan dari median, jumlah orang yang dirugikan akan selalu lebih besar daripada yang diuntungkan, sehingga total jaraknya dijamin bakal membengkak.

> [!TIP]
> Jika diberikan sebuah data integer acak, apakah nilai median dijamin selalu menjadi pilihan yang paling murah untuk menjadi target penyamaan nilai semua data yang ada berdasarkan perhitungan nilai absolut? 

Ya, untuk meminimalkan total selisih absolut (jumlah jarak tanpa kuadrat), median dijamin selalu menjadi pilihan yang paling murah.

Hal ini berlaku untuk semua jenis data integer acak, baik jumlah datanya ganjil maupun genap:

* **Jika jumlah data ganjil:** Hanya ada satu nilai median di tengah-tengah setelah data diurutkan, dan nilai tunggal inilah yang memberikan total biaya minimum mutlak.
* **Jika jumlah data genap:** Ada dua nilai di tengah. Setiap angka bulat (integer) yang berada di dalam rentang antara dua nilai tengah tersebut (inklusif) akan menghasilkan total biaya minimum yang sama persis dan paling murah. Jadi, memilih salah satu dari dua angka tengah tersebut sudah dijamin paling optimal.

*Catatan pengecualian:* Median hanya berlaku untuk meminimalkan *selisih absolut* (seperti pada soal CSES Stick Lengths). Jika yang diminta adalah meminimalkan *kuadrat selisih* (jumlah jarak pangkat dua), maka pilihan paling murah bukan lagi median, melainkan rata-rata (mean).

> [!TIP]
> Sebentar, apakah memilih median tetap menjamin solusi optimal ketika distribusi data sangat ekstrem?
> 
> Misalnya, data pada sisi kiri median meningkat secara linear, sedangkan data pada sisi kanan median meningkat secara eksponensial atau kubik. Apakah median masih menjadi pilihan terbaik untuk kasus dengan distribusi nilai yang tidak seimbang seperti ini?

Ya, median tetap menjamin solusi optimal meskipun distribusi data sangat ekstrem.

Dalam perhitungan selisih absolut, nilai optimal ditentukan oleh jumlah elemen yang berada di sisi kiri dan kanan titik target, bukan dari besaran nilai elemen tersebut. Tujuan utamanya adalah mencari nilai target yang meminimalkan total selisih mutlak.

Meskipun nilai elemen di sebelah kanan median bertambah secara eksponensial atau kubik, menggeser titik target ke arah kanan untuk mendekati nilai ekstrem tersebut adalah langkah yang tidak efisien. Pergeseran tersebut mungkin mengurangi jarak terhadap beberapa elemen ekstrem di kanan, tetapi secara bersamaan akan menambah jarak terhadap seluruh elemen yang berada di sebelah kiri. Karena jumlah elemen di sisi kiri mendominasi saat titik target digeser melewati median, total penambahan jarak di kiri akan jauh lebih besar daripada penghematan jarak di kanan.

Oleh karena itu, titik keseimbangan yang membagi jumlah elemen menjadi dua bagian yang sama, yaitu median, tetap menjadi titik matematis yang meminimalkan total biaya secara mutlak, terlepas dari seberapa tidak seimbangnya rentang nilai data pada kedua sisinya.
## Code Implementation

```cpp
#include <bits/stdc++.h>
using namespace std;

void solve() {
    int n;
    cin >> n;
    vector<long long> stick(n);
    for (auto& x : stick) {
        cin >> x;
    }

    sort(stick.begin(), stick.end());
    long long sum = 0;
    for (int i = 0; i < n; i++) {
        sum += abs(stick[n / 2] - stick[i]);
    }
    cout << sum;
}

auto main() -> int {
    std::ios_base::sync_with_stdio(false);
    std::cin.tie(nullptr);
    int t = 1;
    // cin >> t;
    while (t--) {
        solve();
    }
    return 0;
}
```
