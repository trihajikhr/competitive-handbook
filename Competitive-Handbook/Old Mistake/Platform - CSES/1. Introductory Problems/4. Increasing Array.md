# Increasing Array

![](4.%20Increasing%20Array-1.png)

## Problem

Diberikan sebuah *array* yang terdiri dari $n$ bilangan bulat. Kamu ingin memodifikasi *array* tersebut agar menjadi tidak turun, yaitu setiap elemen bernilai setidaknya sama besar dengan elemen sebelumnya.

Pada setiap langkah, kamu dapat meningkatkan nilai elemen apa pun sebesar satu. Berapa jumlah minimum langkah yang diperlukan?

## Solution

Tetapkan variabel jawaban yang bisa menampung jawaban yang sangat besar untuk bermain aman, misal di C++ adalah menggunakan tipe data `long long`, mari beri nama sebagai $sum$.

Setelah itu, lakukan perulangan dari $2$ hingga $n$, intinya ketika ingin melakukan operasi pemeriksaan dengan $2$ buah data, selalu lakukan perulangan sebanyak $n-1$ untuk menghindari mengakses indeks diluar batas. Pada perulangan ini, lakukan pengecekan dengan nilai disebelah kirinya, yaitu pengecekan apakah $a[i-1] > a[i]$. Jika kondisi ini terpenuhi, maka artinya elemen kiri lebih besar dari elemen sekarang, sehingga akumulasikan jawaban dengan $sum = sum + (a[i-1] - a[i])$, lalu perbarui nilai $a[i] = a[i-1]$ agar bisa digunakan untuk operasi perulangan selanjutnya.
## Proof of Correctness

> [!TIP] 
> Kenapa solusi ini menjamin berhasil?

Solusi ini menjamin berhasil karena memenuhi prinsip *greedy choice property* dan *optimal substructure*, di mana setiap kali kita menemukan elemen yang lebih kecil dari elemen sebelumnya, cara paling minimal untuk memperbaikinya tanpa merusak elemen-elemen sebelumnya adalah dengan menaikkan nilai elemen saat ini tepat sama dengan elemen di sebelah kirinya.

1. **Kebutuhan Minimum pada Setiap Langkah**

	Misalkan kita berada pada elemen ke-$i$ dan mendapati kondisi bahwa elemen sebelumnya lebih besar daripada elemen saat ini ($a[i-1] > a[i]$). Agar *array* menjadi tidak turun, syarat mutlaknya adalah $a[i] \ge a[i-1]$. Karena aturan operasi hanya memperbolehkan kita **menaikkan** nilai elemen, maka jumlah penambahan minimum yang harus diberikan pada $a[i]$ agar memenuhi syarat adalah selisih mutlaknya:
	
	
	$$\Delta = a[i-1] - a[i]$$
	
	
	Jika kita menaikkan $a[i]$ kurang dari $\Delta$, syarat tidak turun tidak akan terpenuhi. Jika kita menaikkannya lebih dari $\Delta$, kita akan membuang-buang langkah (tidak optimal). Oleh karena itu, penambahan sebesar $\Delta$ adalah satu-satunya nilai yang paling efisien untuk posisi $i$.

2. **Tidak Memengaruhi Elemen di Masa Depan secara Negatif**

	Ketika kita mengubah nilai $a[i]$ menjadi sama dengan $a[i-1]$, nilai baru $a[i]$ ini sekarang berada pada posisi setinggi mungkin yang diizinkan oleh elemen kirinya tanpa melakukan perubahan berlebihan.
	
	Saat perulangan berlanjut ke elemen berikutnya ($i+1$), elemen $a[i]$ yang baru saja diperbarui ini bertindak sebagai batas bawah bagi $a[i+1]$. Dengan membuat $a[i]$ sekecil mungkin yang masih valid ($a[i] = a[i-1]$), kita memberikan ruang kebebasan (fleksibilitas) maksimum bagi elemen $a[i+1]$ di masa depan untuk memerlukan sedikit mungkin penambahan, atau bahkan tidak sama sekali jika $a[i+1]$ aslinya sudah lebih besar.

3. **Struktur Optimal Lokal Menuju Global**

	Masalah ini dapat dipecahkan secara optimal dengan *greedy* karena keputusan lokal pada indeks $i$ tidak memiliki efek samping yang merugikan pada elemen-elemen di sebelah kanannya. Setiap elemen hanya bergantung pada tetangga langsungnya di sebelah kiri. Dengan memperbaiki pelanggaran urutan dari kiri ke kanan secara berurutan, kita memastikan bahwa setiap pasangan elemen $(a[i-1], a[i])$ dijamin valid secara independen, yang pada akhirnya membuat seluruh *array* valid dari ujung ke ujung dengan akumulasi biaya yang seminimal mungkin.

> [!TIP]
> Bagaimana jika kita menguji algoritma ini pada sebuah *array* kecil yang melanggar aturan urutan, misalnya $[3, 2, 2]$?

Pada iterasi pertama, kita melihat elemen kedua bernilai 2, yang lebih kecil dari elemen pertamanya yaitu 3. Selisih kekurangannya adalah $3 - 2 = 1$. Jika kita menaikkan elemen kedua menjadi sama dengan elemen pertama, kita menambahkan biaya sebanyak 1, sehingga *array* sementara berubah menjadi $[3, 3, 2]$ dan total biaya menjadi 1. Langkah ini wajib dilakukan karena tidak ada cara lain untuk menyelamatkan elemen kedua agar tidak lebih kecil dari elemen pertama selain menaikkannya, dan menaikkannya sebesar selisih persis adalah pilihan yang paling hemat.

Selanjutnya, pada iterasi kedua, kita melihat elemen ketiga bernilai 2, yang dibandingkan dengan elemen keduanya yang sekarang sudah bernilai 3. Selisih kekurangannya adalah $3 - 2 = 1$. Kita menaikkan elemen ketiga tersebut menjadi 3, sehingga total biaya bertambah lagi 1 menjadi 2, dan *array* akhir berubah menjadi $[3, 3, 3]$.

Dari pembuktian langkah demi langkah ini, terlihat bahwa setiap kali terjadi pelanggaran urutan, menaikkan nilai elemen saat ini agar pas menjadi sama dengan tetangga kirinya adalah satu-satunya tindakan minimal yang logis. Kita tidak mungkin menaikkan kurang dari selisihnya karena akan tetap melanggar aturan, dan kita tidak boleh menaikkan lebih dari selisihnya karena akan menambah biaya secara sia-sia. Karena setiap keputusan lokal diselesaikan secara independen tanpa merusak kemungkinan solusi di masa depan, akumulasi dari langkah-langkah minimal ini dijamin menghasilkan total biaya minimum secara global.

## Code Implementation

```cpp
#include <iostream>
#include <vector>
using namespace std;

auto main() -> int {
    int n;
    cin >> n;
    vector<int> vec(n);
    for (auto& x : vec) {
        cin >> x;
    }

    if (n == 1) {
        cout << 0;
        return 0;
    }

    long long sum = 0;
    for (int i = 1; i < n; i++) {
        if (vec[i] < vec[i - 1]) {
            sum += vec[i - 1] - vec[i];
            vec[i] = vec[i - 1];
        }
    }

    cout << sum;

    return 0;
}
```
