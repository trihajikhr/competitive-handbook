# Coin Combinations I

![](_assets/3.%20Coin%20Combinations%20I-1.png)

## Problem

Pertimbangkan sebuah sistem mata uang yang terdiri dari $n$ koin. Setiap koin memiliki nilai bilangan bulat positif. Tugas Anda adalah menghitung banyaknya cara berbeda untuk menghasilkan jumlah uang $x$ menggunakan koin-koin yang tersedia.

Sebagai contoh, jika koin yang tersedia adalah $\{2,3,5\}$ dan jumlah yang diinginkan adalah $9$, terdapat $8$ cara:

* $2+2+5$
* $2+5+2$
* $5+2+2$
* $3+3+3$
* $2+2+2+3$
* $2+2+3+2$
* $2+3+2+2$
* $3+2+2+2$

## Solution

Persoalan **Coin Combinations I** di CSES menuntut kita untuk menghitung banyaknya cara (kombinasi urutan) untuk membuat nilai total $x$ menggunakan $n$ jenis koin yang diberikan.

Jika kita perhatikan, masalah ini sebenarnya adalah **gabungan dari dua konsep** yang sudah kita bahas sebelumnya:

1. Menggunakan jenis koin variabel seperti pada **Minimizing Coins** (bukan sekadar dadu $1$-$6$).
2. Menghitung banyaknya cara di mana **urutan koin berpengaruh** (permutasi) seperti pada **Dice Combinations**.

### 1. Memahami Inti Masalah

Diberikan $n$ jenis koin $c = \{c_1, c_2, \dots, c_n\}$ dan target nilai $x$. kita diminta mencari banyaknya urutan pengambilan koin yang jumlah total nilainya sama dengan $x$.

Karena urutan diperhitungkan, misal koin yang tersedia adalah $\{2, 3, 5\}$ dan targetnya $7$, maka susunan $(2, 5)$, $(5, 2)$, dan $(2, 3, 2)$ dianggap sebagai **3 cara yang berbeda**.

### 2. Formulasi State DP

* **Definisi State:** $dp[i]$ = banyaknya cara untuk membuat jumlah total nilai $i$.
* **Target:** Mencari nilai dari $dp[x]$.

### 3. Base Case & Inisialisasi

* $dp[0] = 1$: Tepat ada 1 cara untuk membuat nilai 0, yaitu dengan tidak memilih koin sama sekali.
* Seluruh elemen $dp[1 \dots x]$ diinisialisasi dengan $0$.

### 4. Transisi DP (Relasi Rekurens)

Untuk membentuk nilai $i$, bayangkan koin **terakhir** yang kita letakkan. Koin terakhir tersebut bisa berupa salah satu dari jenis koin yang ada di daftar $c$, yaitu $c_j$.

Jika koin terakhir yang dipakai bernilai $c_j$, maka sisa nilai sebelumnya adalah $i - c_j$. Banyak cara untuk membentuk sisa nilai tersebut adalah $dp[i - c_j]$.

Karena setiap pilihan koin terakhir $c_j$ bersifat independen, kita cukup **menjumlahkan** semua kemungkinan dari koin-koin yang nilainya tidak melebihi $i$:

$$dp[i] = \sum_{j=1}^{n} dp[i - c_j] \quad \text{untuk setiap } c_j \le i$$

### 5. Strategi Penyelesaian (Bottom-Up)

1. **Inisialisasi Array:** Buat array $dp$ berukuran $x + 1$ diisi nilai $0$, lalu set $dp[0] = 1$.
2. **Iterasi Target ($i$):** Perulangan luar berjalan dari $i = 1$ sampai $x$. (Ingat: karena urutan berpengaruh, target $i$ harus berada di **luar**).
3. **Iterasi Jenis Koin ($c_j$):** Perulangan dalam memeriksa setiap koin $c_j$ dari daftar koin $c$.
4. **Update State:** Jika $i - c_j \ge 0$, tambahkan $dp[i - c_j]$ ke $dp[i]$.
5. **Aritmatika Modulo:** Lakukan modulo $10^9 + 7$ pada setiap operasi penjumlahan karena nilai jawaban bisa sangat besar.

### Perbandingan Ringkas

* Pada **Dice Combinations**: Pilihan nilai yang ada selalu tetap, yaitu $1$ sampai $6$.
* Pada **Coin Combinations I**: Pilihan nilai di dalam perulangan diganti sesuai daftar koin $c_1, c_2, \dots, c_n$ yang diinputkan.

Logika dasar dan struktur kodenya hampir persis sama dengan Dice Combinations.

## Proof of Correctness

### PoC 1

> [!TIP]
> Jadi, formula yang digunakan hampir mirip seperti soal [*Minimizing Coins*](2.%20Minimizing%20Coins), hanya saja alih-alih mencari banyak koin minimal yang bisa digunakan, disini kita justru mencari banyaknya kemungkinan? 

Tepat sekali. Inti dari persamaan dan perbedaannya berada di titik tersebut.

Kedua masalah ini menggunakan ruang pencarian (*state space*) yang identik, yaitu mencoba setiap koin $c_j$ yang valid sebagai koin terakhir untuk membentuk nilai $i$. Perbedaannya hanya terletak pada fungsi agregasi matematika yang digunakan pada transisi DP-nya.

Pada Minimizing Coins, kita mencari jalur paling efisien (jumlah koin paling sedikit), sehingga fungsi agregasinya menggunakan operasi minimum ($\min$) dengan menambahkan $1$ koin:

$$dp[i] = \min_{j=1}^{n} (dp[i - c_j] + 1)$$

Pada Coin Combinations I, kita tidak peduli berapa banyak koin yang digunakan, melainkan ingin membilang seluruh cabang kemungkinan susunan yang valid. Oleh karena itu, fungsi agregasinya menggunakan operasi penjumlahan ($\sum$) dari seluruh kemungkinan sisa nilai $i - c_j$:

$$dp[i] = \sum_{j=1}^{n} dp[i - c_j]$$

Secara Proof of Correctness (PoC), pembuktiannya persis sama dengan masalah Dice Combinations menggunakan Induksi Matematika Kuat (*Strong Induction*).

Setiap urutan koin yang bernilai total $i$ pasti diakhiri oleh salah satu koin $c_j$. Karena setiap pilihan koin terakhir $c_j$ membentuk himpunan susunan yang saling lepas (*disjoint sets*), maka berdasarkan Aturan Penjumlahan (*Sum Rule*) dalam kombinatorika, total cara membentuk nilai $i$ adalah jumlah dari semua cara membentuk sisa nilai $i - c_j$ untuk setiap $c_j \le i$.

### PoC 2
> [!TIP]
> Jadi $dp[0]$ ini akan menjadi titik mulai dimana semua nilai $dp[i]$ lain menjadi bertambah dan bertambah? Walaupun awalnya hanya bertambah satu (yaitu nilai $dp[0] = 1$), lama kelamaan akan menjadi sangat besar, hingga melebihi $10^9 + 7$?

Tepat sekali. Pengamatanmu sangat akurat mengenai bagaimana informasi "mengalir" di dalam array DP.

Nilai $dp[0] = 1$ bekerja seperti sebuah sumber arus tunggal. Pada awalnya, nilai 1 dari $dp[0]$ ini memicu nilai-nilai $dp[i]$ pertama yang bisa dibentuk langsung oleh satu koin. Misalnya, jika ada koin bernilai 2 dan 3, maka $dp[2]$ dan $dp[3]$ masing-masing akan mendapatkan transfer nilai $1$ dari $dp[0]$.

Seiring bergeraknya iterasi ke target $i$ yang lebih besar, nilai-nilai $dp[i]$ tidak lagi hanya mengambil nilai dari $dp[0]$, melainkan menampung akumulasi penjumlahan dari berbagai $dp[i - c_j]$ sebelumnya yang sudah membesar.

Proses ini menciptakan efek eksponensial (*branching factor*). Satu cara di awal dapat bercabang menjadi ribuan hingga jutaan susunan kombinasi unik di target yang lebih besar. Karena setiap nilai $dp[i]$ terbentuk dari penjumlahan beberapa nilai DP di belakangnya, nilainya akan melesat sangat cepat—mirip seperti deret Fibonacci, tetapi dengan cabang penjumlahan yang lebih banyak tergantung jumlah jenis koin.

Oleh karena itu, untuk target $x$ yang cukup besar, banyaknya kombinasi dengan mudah menembus batas integer biasa dan melebihi $10^9 + 7$, sehingga operasi modulo di setiap penjumlahan menjadi wajib agar tidak terjadi *overflow*.

## Code Implementation

```cpp
#include <iostream>
#include <vector>
using namespace std;

constexpr int M = 1e9 + 7;

auto main() -> int {
    int n, x;
    cin >> n >> x;
    vector<int> coins(n);
    for (int i = 0; i < n; i++) {
        cin >> coins[i];
    }

    vector<int> dp(x + 1, 0);
    dp[0] = 1;

    for (int i = 1; i <= x; i++) {
        for (int j = 0; j < n; j++) {
            if (i >= coins[j]) {
                dp[i] = (dp[i] + dp[i - coins[j]]) % M;
            }
        }
    }

    cout << dp[x];
    return 0;
}
```
