# Edit Distance

![](_assets/10.%20Edit%20Distance-1.png)

## Problem

*Edit distance* antara dua *string* adalah jumlah operasi minimum yang diperlukan untuk mengubah satu *string* menjadi *string* lainnya.

Operasi yang diperbolehkan adalah:

* Menambahkan satu karakter ke dalam *string*.
* Menghapus satu karakter dari *string*.
* Mengganti satu karakter dalam *string*.

Sebagai contoh, *edit distance* antara LOVE dan MOVIE adalah 2, karena Anda dapat mengganti L dengan M terlebih dahulu, kemudian menambahkan I.

Tugas Anda adalah menghitung *edit distance* antara dua *string*.

## Solution

Persoalan **Edit Distance** (juga dikenal sebagai *Levenshtein Distance*) di CSES adalah salah satu masalah DP klasik pada dua string (*two-string sequence alignment*).

### 1. Memahami Inti Masalah

Diberikan dua buah string $s$ dan $t$. Kamu diminta mencari **jumlah operasi minimum** yang diperlukan untuk mengubah string $s$ menjadi string $t$.

Operasi yang diperbolehkan ada 3 jenis:

1. **Insert (Sisip):** Menambahkan satu karakter ke dalam string.
2. **Delete (Hapus):** Menghapus satu karakter dari string.
3. **Replace (Ganti):** Mengubah satu karakter menjadi karakter lain.

Setiap operasi dihitung sebagai $1$ langkah.

### 2. Formulasi State DP

* **Definisi State:** $dp[i][j]$ = jumlah operasi minimum untuk mengubah prefix $s[1 \dots i]$ (panjang $i$) menjadi prefix $t[1 \dots j]$ (panjang $j$).
* **Target:** Mencari nilai dari $dp[n][m]$, di mana $n = \vert{}s\vert{}$ dan $m = \vert{}t\vert{}$.

### 3. Base Case & Inisialisasi

* $dp[0][j] = j$: Mengubah string kosong menjadi string $t$ berpanjang $j$ membutuhkan $j$ kali operasi **Insert**.
* $dp[i][0] = i$: Mengubah string $s$ berpanjang $i$ menjadi string kosong membutuhkan $i$ kali operasi **Delete**.

### 4. Transisi DP (Relasi Rekurens)

Untuk menghitung $dp[i][j]$, kita bandingkan karakter terakhir dari kedua prefix, yaitu $s[i-1]$ dan $t[j-1]$ (menggunakan indeks 0-based):

#### Kasus A: Karakter Sama ($s[i-1] == t[j-1]$)

Tidak diperlukan operasi tambahan pada karakter ini. Biaya operasinya $0$, sehingga nilainya sama dengan mengubah prefix sebelumnya:

$$dp[i][j] = dp[i-1][j-1]$$

#### Kasus B: Karakter Beda ($s[i-1] \neq t[j-1]$)

Kita harus memilih 1 dari 3 kemungkinan operasi yang menghasilkan total biaya terkecil:

1. **Replace:** Mengubah karakter $s[i-1]$ menjadi $t[j-1]$.

$$\text{Biaya} = dp[i-1][j-1] + 1$$


2. **Delete:** Menghapus karakter $s[i-1]$ dari string $s$.

$$\text{Biaya} = dp[i-1][j] + 1$$


3. **Insert:** Menyisipkan karakter $t[j-1]$ ke akhir string $s$.

$$\text{Biaya} = dp[i][j-1] + 1$$



Ambil nilai minimum dari ketiga pilihan tersebut:

$$dp[i][j] = 1 + \min(dp[i-1][j-1], \; dp[i-1][j], \; dp[i][j-1])$$

### 5. Strategi Penyelesaian (Bottom-Up)

1. **Inisialisasi Matrix:** Buat matriks $dp[n+1][m+1]$.
2. **Set Base Case:**
	* $dp[i][0] = i$ untuk $0 \le i \le n$.
	* $dp[0][j] = j$ untuk $0 \le j \le m$.


3. **Iterasi 2D:**
	* Perulangan baris $i$ dari $1$ sampai $n$.
	* Perulangan kolom $j$ dari $1$ sampai $m$.
	* Terapkan transisi berdasarkan apakah $s[i-1] == t[j-1]$.

4. **Output:** Cetak $dp[n][m]$.

### Optimasi Ruang (Space Optimization)

Baris $dp[i]$ pada matriks hanya membutuhkan nilai dari baris saat ini ($i$) dan baris sebelumnya ($i-1$). Penggunaan memori dapat dipangkas dari $O(n \cdot m)$ menjadi $O(m)$ dengan menggunakan dua array 1D berukuran $m+1$.

## Proof of Correctness
### PoC 1

> [!TIP]
> Kenapa pengisian $dp[i][j]$ dilakukan dari  depan, tapi pengecekan dimulai dari belakang string dengan s[i-1]$ dan $t[j-1]$?

Berikut adalah Proof of Correctness (PoC) mengenai mekanisme indexing dan pembacaan karakter pada **Edit Distance**.

#### 1. Perbedaan *Length-based State* dan *0-based Array Indexing*

Dalam Dynamic Programming untuk operasi string, *state* $dp[i][j]$ didefinisikan berdasarkan **panjang prefix** (*prefix length*), bukan indeks karakter.

* Sub-masalah $dp[i][j]$ mewakili pengubahan prefix $s$ berpanjang $i$ menjadi prefix $t$ berpanjang $j$.
* Ukuran matriks DP adalah $(n+1) \times (m+1)$, di mana baris ke-$0$ dan kolom ke-$0$ dialokasikan khusus untuk *base case* (string kosong).

Karena string dalam C++ menggunakan sistem *0-based indexing*:

* Karakter **terakhir** dari prefix $s$ berpanjang $i$ berada pada indeks $i-1$.
* Karakter **terakhir** dari prefix $t$ berpanjang $j$ berada pada indeks $j-1$.

Pengisian tabel DP dilakukan dari depan (indeks prefix $i = 1 \dots n$ dan $j = 1 \dots m$), tetapi saat mengevaluasi transisi untuk prefix berpanjang $i$ dan $j$, karakter fisik yang sedang dibandingkan tepat di batas akhir prefix tersebut adalah $s[i-1]$ dan $t[j-1]$.

#### 2. Sifat Induktif dan Optimal Substructure

Pendekatan *Bottom-Up* membangun solusi dari sub-masalah kecil ke sub-masalah besar.

Untuk menentukan jumlah operasi minimum mengubah prefix $s[1 \dots i]$ menjadi $t[1 \dots j]$, asumsi dasarnya adalah bahwa kita **sudah mengetahui** solusi optimal untuk seluruh prefix yang lebih pendek:

1. $dp[i-1][j-1]$ (solusi optimal untuk prefix $s[1 \dots i-1]$ dan $t[1 \dots j-1]$)
2. $dp[i-1][j]$ (solusi optimal untuk prefix $s[1 \dots i-1]$ dan $t[1 \dots j]$)
3. $dp[i][j-1]$ (solusi optimal untuk prefix $s[1 \dots i]$ dan $t[1 \dots j-1]$)

Pengecekan dilakukan pada karakter paling akhir dari prefix saat ini ($s[i-1]$ dan $t[j-1]$) karena karakter tersebut adalah **satu-satunya elemen baru** yang membedakan prefix $(i, j)$ dari sub-masalah $(i-1, j-1)$, $(i-1, j)$, dan $(i, j-1)$ yang sudah terpecahkan sebelumnya.

#### 3. Pemetaan Transisi Keputusan

Dengan membandingkan karakter batas $s[i-1]$ dan $t[j-1]$, keputusan dipetakan secara presisi ke sub-masalah yang sesuai:

1. **Jika $s[i-1] == t[j-1]$:**
	Karakter paling akhir dari kedua prefix sudah cocok. Tidak ada operasi yang perlu dilakukan pada posisi ini. Masalah direduksi secara langsung ke penyelesaian prefix sebelumnya:
	
	$$dp[i][j] = dp[i-1][j-1]$$


1. **Jika $s[i-1] \neq t[j-1]$:**
   Karakter paling akhir tidak cocok. Kita harus memilih salah satu dari 3 tindakan pada karakter akhir tersebut:
	* **Replace $s[i-1]$ dengan $t[j-1]$:** Mengubah karakter paling akhir agar cocok, lalu menyisakan sub-masalah $dp[i-1][j-1] + 1$.
	* **Delete $s[i-1]$:** Menghapus karakter akhir dari $s$, sehingga prefix $s$ berkurang menjadi panjang $i-1$ untuk mencocokkan $t$ berpanjang $j$, menyisakan sub-masalah $dp[i-1][j] + 1$.
	* **Insert $t[j-1]$ ke $s$:** Menambahkan karakter di akhir $s$ agar cocok dengan karakter akhir $t$, sehingga target $t$ berkurang menjadi panjang $j-1$, menyisakan sub-masalah $dp[i][j-1] + 1$.
#### Kesimpulan

Pemeriksaan $s[i-1]$ dan $t[j-1]$ bukanlah pengecekan "dari belakang string secara keseluruhan", melainkan pengecekan **elemen paling kanan dari prefix yang sedang diproses saat ini**. Pengisian DP tetap berjalan dari depan ke belakang (*topological order* dari DAG sub-masalah) untuk menjamin bahwa seluruh nilai $dp[i-1][j-1]$, $dp[i-1][j]$, dan $dp[i][j-1]$ sudah tersedia dan valid saat $dp[i][j]$ dihitung.

### PoC 2

> [!TIP]
> Bagaimana pemeriksaan ke tiga arah, yaitu $dp[i-1][j-1], dp[i-1][j], dp[i][j-1]$ bisa bekerja dengan sangat baik untuk membentuk rekurens *dynammic programming*?

Berikut adalah Proof of Correctness (PoC) 2 mengenai keabsahan dan kelengkapan eksplorasi **tiga arah transisi** pada algoritma Edit Distance.

#### 1. Struktur Ruang Keputusan (*Decision Space*)

Untuk mengubah prefix $s[1 \dots i]$ menjadi $t[1 \dots j]$, karakter terakhir dari $s[1 \dots i]$ (yaitu $s[i-1]$) dan karakter terakhir dari $t[1 \dots j]$ (yaitu $t[j-1]$) harus diselaraskan (*aligned*).

Secara matematis, dalam *sequence alignment*, hanya ada **tiga kemungkinan hubungan akhir** yang sah antara kedua prefix tersebut:

1. **Alignment Diagonal ($s[i-1]$ dipasangkan langsung dengan $t[j-1]$):**
	* Jika karakter sama, biayanya $0$.
	* Jika karakter berbeda, karakter $s[i-1]$ diganti (*Replace*) menjadi $t[j-1]$ dengan biaya $1$.
	* Keputusan ini menyelesaikan karakter $s[i-1]$ dan $t[j-1]$ secara bersamaan, mereduksi masalah ke penyelarasan $s[1 \dots i-1]$ dan $t[1 \dots j-1]$.
	* **Representasi DP:** $dp[i-1][j-1] + \text{cost}$


2. **Deletion Vertical ($s[i-1]$ tidak memiliki pasangan di $t[1 \dots j]$):**
	* Karakter $s[i-1]$ dibuang (*Delete*) dengan biaya $1$.
	* Keputusan ini menghilangkan karakter $s[i-1]$, mereduksi masalah ke penyelarasan sisa prefix $s[1 \dots i-1]$ dengan $t[1 \dots j]$.
	* **Representasi DP:** $dp[i-1][j] + 1$


3. **Insertion Horizontal ($t[j-1]$ tidak memiliki pasangan di $s[1 \dots i]$):**
	* Karakter $t[j-1]$ disisipkan (*Insert*) ke akhir $s$ dengan biaya $1$.
	* Keputusan ini memenuhi kebutuhan karakter $t[j-1]$, mereduksi masalah ke penyelarasan $s[1 \dots i]$ dengan sisa prefix $t[1 \dots j-1]$.
	* **Representasi DP:** $dp[i][j-1] + 1$


#### 2. Sifat Exhaustive & Mutual Exclusion (Kelengkapan Transisi)

Tiga arah pergerakan pada matriks DP mewakili seluruh kisi pergerakan dalam grafik grid transisi:

$$\begin{array}{ccc} dp[i-1][j-1] & \xrightarrow{\text{Insert } t[j-1]} & dp[i-1][j] \\ \Big\downarrow \text{\scriptsize Replace/Match} & \searrow \text{\scriptsize Direct} & \Big\downarrow \text{\scriptsize Delete } s[i-1] \\ dp[i][j-1] & \xrightarrow{\text{Delete } s[i-1]} & dp[i][j] \end{array}$$

* **Kelengkapan (*Exhaustive*):** Tidak ada operasi keempat yang sah secara definisi masalah. Setiap pengeditan string dapat diuraikan secara mutlak menjadi kombinasi dari *Replace/Match* (Diagonal), *Delete* (Vertikal), dan *Insert* (Horizontal).
* **Prinsip Optimalitas Bellman:** Karena ketiga arah ini mencakup **seluruh ruang keputusan yang mungkin**, dengan mengambil nilai minimum dari ketiganya:

$$dp[i][j] = \min \begin{cases}  dp[i-1][j-1] + \text{cost} \\  dp[i-1][j] + 1 \\  dp[i][j-1] + 1  \end{cases}$$

solusi yang dihasilkan dijamin optimal secara mutlak tanpa ada kemungkinan jalur transformasi yang terlewat.

#### 3. Pembuktian Induksi Matematika

* **Base Case:**
	* $dp[0][j] = j$ (hanya bisa dicapai lewat $j$ kali *Insert* / pergerakan horizontal).
	* $dp[i][0] = i$ (hanya bisa dicapai lewat $i$ kali *Delete* / pergerakan vertikal).
	Keduanya benar secara definisi.


* **Hipotesis Induksi:**
  Asumsikan untuk semua sel $(r, c)$ dengan $r + c < i + j$, nilai $dp[r][c]$ secara tepat menyimpan jumlah operasi minimum untuk mengubah $s[1 \dots r]$ menjadi $t[1 \dots c]$.
* **Langkah Induksi:**
	Untuk sel $(i, j)$:
	* Tetangga diagonal $(i-1, j-1)$ memiliki sum $i + j - 2 < i + j$.
	* Tetangga atas $(i-1, j)$ memiliki sum $i + j - 1 < i + j$.
	* Tetangga kiri $(i, j-1)$ memiliki sum $i + j - 1 < i + j$.

Berdasarkan hipotesis induksi, ketiga nilai pendukung tersebut sudah bernilai optimal. Karena langkah terakhir menuju $(i, j)$ wajib datang dari salah satu dari tiga sel tersebut, operasi $\min()$ di atas dijamin memilih jalur transformasi paling efisien menuju $(i, j)$.
## Code Implementation

```cpp
#include <algorithm>
#include <iostream>
#include <string>
#include <vector>
using namespace std;

auto main() -> int {
    string s, t;
    cin >> s >> t;

    int n = (int)s.length();
    int m = (int)t.length();
    vector<vector<int>> dp(n + 1, vector<int>(m + 1));

    for (int i = 0; i <= n; i++) dp[i][0] = i;
    for (int j = 0; j <= m; j++) dp[0][j] = j;

    for (int i = 1; i <= n; i++) {
        for (int j = 1; j <= m; j++) {
            if (s[n - i] == t[m - j]) {
                dp[i][j] = dp[i - 1][j - 1];
            } else {
                dp[i][j] = min({dp[i - 1][j - 1], dp[i][j - 1], dp[i - 1][j]}) + 1;
            }
        }
    }

    cout << dp[n][m];
    return 0;
}
```
