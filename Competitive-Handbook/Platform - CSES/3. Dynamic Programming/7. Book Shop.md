# Book Shop

![](_assets/7.%20Book%20Shop-1.png)

## Problem

Anda berada di sebuah toko buku yang menjual $n$ buku berbeda. Anda mengetahui harga dan jumlah halaman dari setiap buku.

Anda telah memutuskan bahwa total harga pembelian Anda paling banyak $x$. Berapa jumlah halaman maksimum yang dapat Anda beli? Anda dapat membeli setiap buku paling banyak satu kali.

## Solution

Akhirnya kita sampai di salah satu masalah klasik paling fundamental dalam Dynamic Programming: **0/1 Knapsack Problem**.

Di CSES, masalah ini dibungkus dengan nama **Book Shop**.

### 1. Memahami Inti Masalah

Kamu memiliki anggaran uang sebesar $x$. Di toko buku terdapat $n$ buah buku.
Setiap buku $i$ memiliki dua informasi:

1. **Harga (*price*)** $h_i$: biaya yang harus dibayar untuk membeli buku tersebut.
2. **Jumlah halaman (*pages*)** $s_i$: manfaat/nilai yang kamu dapatkan dari buku tersebut.

Aturan utamanya: **Setiap buku hanya bisa dibeli maksimal 1 kali** (tidak bisa dipotong, tidak bisa dibeli berulang kali—inilah mengapa disebut **0/1** Knapsack: opsi pilih $= 1$, abaikan $= 0$).

Tujuannya adalah memilih kombinasi buku sedemikian rupa sehingga total harga tidak melebihi anggaran $x$, dan total jumlah halaman yang diperoleh adalah **maksimum**.

### 2. Formulasi State DP

* **Definisi State:** $dp[i][w]$ = jumlah halaman maksimum yang bisa didapatkan menggunakan **subset dari $i$ buku pertama** dengan **maksimal anggaran $w$**.
* **Target:** Mencari nilai dari $dp[n][x]$.

### 3. Base Case & Inisialisasi

* $dp[0][w] = 0$ untuk semua $0 \le w \le x$: Jika tidak ada buku yang tersedia, jumlah halaman yang didapat adalah 0.
* $dp[i][0] = 0$ untuk semua $0 \le i \le n$: Jika anggaran adalah 0, tidak ada buku yang bisa dibeli.

### 4. Transisi DP (Relasi Rekurens)

Saat kita berada di buku ke-$i$ dengan anggaran $w$, ada 2 pilihan:

1. **Abaikan buku ke-$i$:** Total halaman sama dengan hasil terbaik dari $i-1$ buku pertama dengan anggaran yang sama.

$$\text{Opsi 1} = dp[i-1][w]$$


2. **Beli buku ke-$i$** (hanya valid jika anggarannya cukup, yaitu $w \ge h_i$):
	Sisa anggaran menjadi $w - h_i$. Total halaman adalah halaman dari buku ke-$i$ ($s_i$) ditambah hasil terbaik dari $i-1$ buku sebelumnya dengan sisa anggaran $w - h_i$.
	
	$$\text{Opsi 2} = dp[i-1][w - h_i] + s_i$$
	


Karena kita ingin memaksimalkan jumlah halaman, ambil nilai terbesar di antara kedua pilihan tersebut:

$$dp[i][w] = \begin{cases} dp[i-1][w] & \text{jika } w < h_i \\ \max(dp[i-1][w], dp[i-1][w - h_i] + s_i) & \text{jika } w \ge h_i \end{cases}$$


### 5. Optimasi Ruang (Space Optimization) dari $O(n \cdot x)$ ke $O(x)$

Jika menggunakan array 2D $dp[n+1][x+1]$, memori yang dibutuhkan bisa terlalu besar (hingga $1000 \times 10^5 \approx 10^8$ elemen `int` $\approx 400$ MB, yang bisa memicu *Memory Limit Exceeded*).

Perhatikan bahwa baris ke-$i$ hanya bergantung pada baris sebelumnya, yaitu $i-1$. Kita bisa memangkasnya menjadi array 1D $dp[w]$ berukuran $x+1$.

**Kunci penting 0/1 Knapsack pada Array 1D:**
Perulangan anggaran $w$ harus berjalan **MUNDUR** (dari $x$ turun ke $h_i$).

```cpp
for (int i = 0; i < n; i++) {
    for (int w = x; w >= h[i]; w--) {
        dp[w] = max(dp[w], dp[w - h[i]] + s[i]);
    }
}
```

Kenapa harus berjalan mundur? Agar nilai $dp[w - h_i]$ yang dibaca adalah nilai dari **iterasi buku sebelumnya ($i-1$)**, bukan nilai yang sudah diperbarui oleh buku saat ini ($i$). Jika berjalan maju, satu buku yang sama bisa terpakai berkali-kali (berubah menjadi *Unbounded Knapsack* seperti pada Coin Combinations).

## Proof of Correctness
### PoC 1

> [!TIP]
> Apa ciri-ciri persoalan *0/1 knapsack*?


Berikut adalah bukti kebenaran (Proof of Correctness) mengenai identifikasi dan karakterisasi masalah *0/1 Knapsack*. Sebuah persoalan *Dynamic Programming* dapat dikategorikan secara mutlak sebagai *0/1 Knapsack Problem* jika memenuhi empat struktur kondisi utama.

1. Pertama, terdapat himpunan elemen diskrit dan terbatas. Diberikan $n$ buah item terhitung, di mana setiap item $i \in \{1, 2, \dots, n\}$ memiliki dua properti kuantitatif utama, yaitu bobot atau harga ($h_i$ atau $w_i$) yang merepresentasikan konsumsi terhadap kapasitas yang tersedia, serta nilai atau keuntungan ($s_i$ atau $v_i$) yang merepresentasikan hasil yang diperoleh dari item tersebut.

2. Kedua, ruang keputusan bersifat biner dan eksklusif. Untuk setiap item $i$, ruang keputusan yang tersedia tepat berupa dua pilihan:

	$$x_i \in \{0, 1\}$$

	Di mana $x_i = 1$ menandakan bahwa item $i$ diambil secara utuh, sedangkan $x_i = 0$ menandakan bahwa item $i$ diabaikan sama sekali. Karakteristik ini menegaskan dua hal penting: item tidak dapat dibagi menjadi bagian fraksional (karena jika dapat dibagi, masalah ini menjadi *Fractional Knapsack* yang diselesaikan dengan pendekatan *Greedy*), dan item tidak dapat diambil lebih dari satu kali (karena jika dapat diambil tanpa batas, masalah ini dikategorikan sebagai *Unbounded Knapsack*, seperti pada problem Coin Combinations).

3. Ketiga, terdapat batasan kapasitas tunggal. Terdapat sebuah batas atas kapasitas $x$ (atau $W$) yang tidak boleh dilampaui oleh total bobot dari item-item yang terpilih:

	$$\sum_{i=1}^{n} x_i \cdot h_i \le x$$

4. Keempat, adanya fungsi tujuan pemaksimalan atau peminimalan. Tujuan utama persoalan ini adalah memaksimalkan total nilai dari item-item yang terpilih:

$$\text{Maksimalkan } \sum_{i=1}^{n} x_i \cdot s_i$$

Sebagai penjelas, berikut adalah perbandingan karakteristik antara *0/1 Knapsack* dan *Unbounded Knapsack*:

* Batas Penggunaan Item: Pada *0/1 Knapsack* (seperti pada problem Book Shop) penggunaan item maksimal 1 kali per item, sedangkan pada *Unbounded Knapsack* (seperti pada problem Coin Combinations) penggunaan item tidak terbatas.
* Arah Loop Kapasitas pada 1D DP: Pada *0/1 Knapsack*, iterasi kapasitas dilakukan secara mundur ($x \to h_i$). Sebaliknya, pada *Unbounded Knapsack*, iterasi dilakukan secara maju ($c_j \to x$).
* Ketergantungan State: Pada *0/1 Knapsack*, komputasi membaca state dari iterasi sebelumnya ($i-1$). Pada *Unbounded Knapsack*, komputasi membaca state dari iterasi yang sedang berjalan ($i$).
## Code Implementation

```cpp
#include <algorithm>
#include <iostream>
#include <vector>
using namespace std;

auto main() -> int {
    int n, x;
    cin >> n >> x;
    vector<int> book(n + 1, 0), page(n + 1, 0);
    for (int i = 1; i <= n; i++) {
        cin >> book[i];
    }

    for (int i = 1; i <= n; i++) {
        cin >> page[i];
    }

    vector<int> dp(x + 1, 0);

    for (int i = 1; i <= n; i++) {
        for (int w = x; w >= book[i]; w--) {
            dp[w] = max(dp[w], dp[w - book[i]] + page[i]);
        }
    }

    cout << dp[x];
    return 0;
}
```
