# Common Divisors
Pada problem ini, diberikan sebuah array dengan ukuran $n$. Tugas kita adalah mencari nilai GCD atau FPB antara dua pasang elemen array dengan nilai semaksimal mungkin. Batasan dari problem ini adalah $2 \le n \le 2 \cdot 10^5$ untuk ukuran array, dan juga $1 \le x_i \le 10^6$ untuk elemen array.

## Intuisi awal yang salah

Jika kita menggunakan nested loop untuk mencari secara berpasangan, dua buah array yang memiliki nilai GCD terbesar, maka kompleksitas algoritmanya menjadi $O(n^2)$, yang mana jelas akan terkena *Time Limit Exceed*:

```cpp
#include <iostream>
#include <numeric>
#include <vector>
using namespace std;
 
auto main() -> int {
    std::ios_base::sync_with_stdio(false);
    std::cin.tie(nullptr);
    int n;
    cin >> n;
    vector<int> vec(n);
    for (auto& x : vec) {
        cin >> x;
    }
 
    int maks = 0;
    for (int i = 0; i < n - 1; i++) {
        int temp = 0;
        for (int j = i + 1; j < n; j++) {
            temp = max(temp, gcd(vec[i], vec[j]));
        }
        maks = max(maks, temp);
    }
 
    cout << maks;
 
    return 0;
}
```

Kode diatas menjalankan 2 kali nested loop, tapi pendekatan ini jelas tidak efisien!

Perbaikan dilakukan dengan menggunakan intuisi bahwa, jika elemen array disorting secara descending dan pencarian dilakukan dari elemen terbesar terlebih dahulu, misal $g$, maka jjika elemen terbesar memiliki pembagi yang nilainya sama atau lebih kecil dari nilai $g$ tersebut, maka kita sudah berhasil mendapatkan kandidat terbesar untuk jawaban, sehingga nested loop bisa dihentikan lebih cepat untuk berlanjut ke elemen lebih kecil selanjutnya, seperti berikut:

```cpp
#include <algorithm>
#include <iostream>
#include <vector>
using namespace std;
 
auto main() -> int {
    std::ios_base::sync_with_stdio(false);
    std::cin.tie(nullptr);
    int n;
    cin >> n;
    vector<int> vec(n);
    for (int i = 0; i < n; i++) {
        cin >> vec[i];
    }
 
    sort(vec.rbegin(), vec.rend());
    int ans = 0;
 
    for (int i = 0; i < n; i++) {
        for (int j = i + 1; j < n; j++) {
            if (vec[i] % vec[j] == 0) {
                ans = max(ans, vec[j]);
                break;
            }
        }
    }
 
    cout << ans;
 
    return 0;
}
```

Namun, solusi tetap menghasilkan jawaban yang salah, atau tetap terkena *Time Limit Exceed*, karena pada kasus terburuk, nilai dari setiap elemen dalam array bisa saja dibuat semuanya prima, sehingga mekanisme *early stop* dengan break tidak akan pernah dijalankan. Akibatnya, kompleksitas akan kembali ke $O(n^2)$, lagi-llagi menjadi tidak efisien!

## Pendekatan yang lebih baik

Daripada menyimpan nilai-nilai tersebut pada array dan harus melakukan sorting untuk memulai pencarian dari nilai terbesar, mungkin akan jauh lebih baik untuk cukup menyimpan frekuensi angka-angka yang diterima, dan menggunakan perulangan $i$ yang dimulai dari $10^6$ hingga $1$, lalu mencari apakah ada elemen pada array yang merupakan kelipatan dari $i$. Jika ada minimal $2$ elemen yang merupakan kelipatan dari $i$, maka nilai tersebut sudah pasti adalah jawabanya.

Untuk menjalankan mekanisme pencarian kelipatan, digunakan perulangan kedua yang berguna untuk menjalankan operasi $i \times j$, yang kemudian hasil dari operasi tersebut digunakan untuk mengecek, apakah ada elemen yang memiliki nilai tersebut, dan menjumlahkan frekuensinya. Jika frekuensinya lebih dari $2$, maka artinya jawaban ditemukan:

> Intuisi! Misal $i=10, j=1$, maka didapat $10 \times 1=10$. Lalu kita mencari kelipatan selanjutnya dari nilai ini, maka akan didapat $20,30,dst$. Jika ada minimal 2 elemen yang merupakan kelipatan $10$, maka $gcd(10,[20, \dots])$ akan menghasilkan nilai terbesar, sehingga langsung hentikan pencarian!

```cpp
#include <iostream>
#include <map>
using namespace std;
 
auto main() -> int {
    std::ios_base::sync_with_stdio(false);
    std::cin.tie(nullptr);
    int n, maks = 0;
    cin >> n;
    map<int, int> dasmap;
    for (int i = 0, x; i < n; i++) {
        cin >> x;
        maks = max(maks, x);
        dasmap[x]++;
    }
 
    for (int i = 1e6; i > 0; i--) {
        int cnt = 0;
        for (int j = 1; j * i <= maks; j++) {
            if (dasmap[i * j] > 0) {
                cnt += dasmap[i * j];
            }
            if (cnt >= 2) {
                cout << i;
                return 0;
            }
        }
    }
 
    return 0;
}
```

Walaupun perulangan kedua ini lebih efisien, karena akan berhenti ketika nilai $i \times j \le max(a)$, namun ternyata lagi-lagi terkena batasan waktu. Ada 3 test case yang terkena batasan waktu dari algoritma diatas, kenapa?

Ini karena penggunaan struktur data `map` memiliki kompleksitas akses berupa $O(log \;n)$, yang mana jika dilakukan berkali-kali, menjadikanya sedikit melebihi batas waktu.

## Perbaikan final
Perbaikan dilakukan dengan kembali menggunakan struktur data array, namun kali ini digunakan untuk menyimpan frekuensi, dan juga pencarian pada perulangan pertama tidak dilakukan mulai dari $10^6$, melainkan dari nilai maksimal dari elemen. Penggunaan struktutur data array seperti `vector` dipilih karena kompleksitas akses datanya adalah konstan $O(1)$, sehingga jauh lebih cepat daripada menggunakan `map`.

Berikut adalah perbaikan yang benar dan diaccepted:

```cpp
#include <iostream>
#include <vector>
using namespace std;

auto main() -> int {
    std::ios_base::sync_with_stdio(false);
    std::cin.tie(nullptr);
    int n, maks = 0;
    cin >> n;
    vector<int> freq(1e6 + 1, 0);
    for (int i = 0, x; i < n; i++) {
        cin >> x;
        maks = max(maks, x);
        freq[x]++;
    }

    for (int i = maks; i > 0; i--) {
        int cnt = 0;
        for (int j = 1; j * i <= maks; j++) {
            if (freq[i * j] > 0) {
                cnt += freq[i * j];
            }
            if (cnt >= 2) {
                cout << i;
                return 0;
            }
        }
    }

    return 0;
}
```

Dengan menggunakan pendekatan ini, kompleksitas menjadi tereduksi menjadi $O(MAX \; log \; MAX)$.
