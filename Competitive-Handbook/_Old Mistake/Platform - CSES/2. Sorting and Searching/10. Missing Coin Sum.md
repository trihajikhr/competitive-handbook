# Missing Coin Sum

## Problem
Kamu mempunyai $n$ buah koin dengan nilai integer positif. Berapakah jumlah terkecil yang tidak dapat kamu buat menggunakan suatu subset dari koin-koin tersebut?

## Solution
Urutkan array secara *ascending*, ini karena kita perlu memproses angka-angka terkecil terlebih dahulu, dan ini juga sesuai seperti yang diminta oleh soal, dimana kita diminta untuk mencari jumlah terkecil yang tidak bisa disusun.

Suatu jumlah terkecil yang tidak bisa dibuat oleh subset dari array tersebut, hanya mungkin terjadi jika semisal akumulasi dari angka-angka terkecil tertentu, memiliki jumlah lebih kecil dengan selisih $> 1$, dengan elemen berikutnya yang lebih besar di sebelah kanan.

Ketika akumulasi penjumlahan dari angka-angka yang sudah diproses gagal menjembatani nilai elemen berikutnya (artinya elemen berikutnya lebih besar dari $akumulasi + 1$), maka titik terputusnya rentang tersebut langsung memperlihatkan nilai terkecil yang gagal dibentuk.

Tapi jika hingga akhir tidak ada gap, maka otomatis nilai terkecil yang bisa dibentuk dari subset array adalah jumlah semua elemen array itu sendiri $+1$, atau:

$$\sum_{i=1}^{n}a_i +1$$

## Proof of Correctness

> [!TIP]
> Kenapa harus diproses dari elemen terkecil? Kenapa harus disorting secara *ascending*?

Urutan array secara *ascending* diperlukan karena kita perlu memproses angka-angka terkecil terlebih dahulu untuk membangun representasi nilai dari bawah ke atas secara *greedy*, sekaligus memastikan bahwa semua kombinasi atau akumulasi nilai sekecil mungkin telah dieksplorasi sebelum melangkah ke nilai yang lebih besar.

Jika tidak diurutkan dari yang terkecil, kita akan kehilangan sifat monotonik dari rentang nilai yang bisa dibentuk, sehingga mustahil untuk menjamin apakah akumulasi dari elemen-elemen sebelumnya sudah mampu mencakup seluruh celah angka dari $1$ sampai $akumulasi$.

Dengan memproses elemen terkecil terlebih dahulu, setiap koin baru bernilai $x_i$ dapat diuji secara langsung terhadap batas rentang kumulatif yang sudah terbentuk sebelumnya, sehingga kemunculan selisih $> 1$ terhadap elemen yang lebih besar di sebelah kanannya dapat terdeteksi secara akurat pada kemunculan pertama.

> [!TIP]
> Kenapa solusi ini menjamin bahwa selama $akumulasi \le x_i$, maka semua subset dari $[1, akumulasi]$ pasti didapat?

Hal tersebut dijamin karena kita menggunakan prinsip induksi matematika atau perluasan rentang secara bertahap.

Katakanlah dari elemen-elemen sebelumnya, kita sudah berhasil membentuk semua angka dari $1$ sampai $akumulasi$ secara rapat tanpa ada satupun angka yang terlewat.

Ketika kita kedatangan koin baru bernilai $x_i$ dan aturan pertama terpenuhi, yaitu $x_i \le akumulasi + 1$ (atau jika dituliskan dalam bentuk akumulasi $\ge x_i - 1$), kita bisa mengambil setiap angka lama yang sudah ada di dalam rentang $[1, akumulasi]$ lalu menjumlahkannya dengan koin baru $x_i$.

Proses penambahan ini akan menghasilkan rentang nilai baru yang dimulai dari $1 + x_i$ sampai $akumulasi + x_i$. Karena nilai $x_i$ ini lebih kecil atau sama dengan batas akumulasi sebelumnya, rentang nilai yang baru ini akan beririsan langsung atau menyambung mulus tanpa celah dengan rentang lama $[1, akumulasi]$.

Akibatnya, gabungan antara rentang lama dan rentang hasil penjumlahan dengan koin baru tersebut akan memperluas cakupan angka yang bisa dibentuk menjadi sebuah rentang baru yang utuh dari $1$ hingga $akumulasi + x_i$, sehingga keterurutan dan kelengkapan subsetnya dijamin selalu terjaga.

> [!TIP]
> Jadi, selama $x_i \le akumulasi$, maka semua bilangan dari $[1, akumulasi + x_i]$ dijamin bisa dibentuk? 

Betul sekali. Jika kondisi $x_i \le akumulasi + 1$ terpenuhi (atau secara sederhana $x_i \le akumulasi$ ditambah satu langkah transisinya), maka rentang bilangan yang bisa dibentuk akan langsung melebar dan menyambung tanpa celah dari $1$ sampai $akumulasi + x_i$.

Semua bilangan di dalam rentang baru tersebut dijamin pasti bisa dibentuk karena sebagian besar sudah bisa dibuat oleh akumulasi sebelumnya, dan sisanya dibentuk dari kombinasi antara koin baru $x_i$ dengan angka-angka yang ada di rentang lama.

> [!TIP]
> Kenapa harus menggunakan $akumulasi+1$ untuk mendeteksi gap?

Kita harus menggunakan $akumulasi + 1$ karena nilai tersebut merepresentasikan **angka terkecil yang belum bisa kita buat** setelah mempertimbangkan semua elemen yang sudah diproses sebelumnya.

Jika semua angka dari $1$ sampai $akumulasi$ sudah pasti terbentuk, maka angka berikutnya yang paling krusial untuk diuji adalah $akumulasi + 1$.

Ketika kita menemui elemen baru $x_i$, ada dua kemungkinan kondisi:

* Jika $x_i \le akumulasi + 1$, artinya elemen baru ini cukup kecil untuk menyambung langsung atau menimpa angka $akumulasi + 1$, sehingga rentang yang bisa dibentuk akan melebar mulus sampai $akumulasi + x_i$. Tidak ada gap di sini.
* Jika $x_i > akumulasi + 1$, artinya elemen baru tersebut terlalu besar untuk menjembatani angka $akumulasi + 1$. Karena elemen-elemen sebelumnya maksimal hanya bisa membentuk angka hingga $akumulasi$, dan elemen setelahnya langsung loncat ke $x_i$, maka angka $akumulasi + 1$ dipastikan tidak akan pernah bisa tercapai oleh kombinasi subset apa pun.

Itulah sebabnya $akumulasi + 1$ menjadi batas mutlak untuk mendeteksi apakah ada celah atau tidak.
## Code Implementation


```cpp
#include <bits/stdc++.h>

#ifdef LOCAL
#include "schematics.hpp"
static_assert(schematics::invariant);
#else
#define debug(...)
#endif

using namespace std;

void solve() {
    int n;
    cin >> n;
    vector<long long> vec(n);
    for (auto& x : vec) {
        cin >> x;
    }

    sort(vec.begin(), vec.end());
    long long sum = 0;
    for (int i = 0; i < n; i++) {
        if (vec[i] <= sum + 1) {
            sum += vec[i];
        } else {
            cout << sum + 1;
            return;
        }
    }
    cout << sum + 1;
}

auto main() -> int {
    std::ios_base::sync_with_stdio(false);
    std::cin.tie(nullptr);
    int t = 1;
    // cin >> t;
    while (t--) {
        solve();
    }
    return 0;
}
```
