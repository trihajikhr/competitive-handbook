# Collecting Numbers

## Problem

Diberikan sebuah *array* yang berisi setiap angka antara 1 sampai $n$ tepat sekali. Tugasmu adalah mengumpulkan angka-angka dari $1$ hingga $n$ secara berurutan dari terkecil ke terbesar.

Pada setiap putaran, kamu berjalan melalui *array* dari kiri ke kanan dan mengumpulkan sebanyak mungkin angka yang memenuhi urutan. Berapa total putaran yang diperlukan?

## Solution

Tampung data dalam dalam array yang bisa menyimpan dua data secara berpasangan. Data utama ditampung di urutan pertama, sedangkan indeksnya ditampung di urutan kedua, ini penting supaya fase sorting selanjutnya, urutan asli dari data yang masuk tidak hilang. Lalu sorting array tersebut secara *ascending*. 

Setelah tersorting, lakukan perulangan dari $1$ hingga $n$, dan akumulasikan ada berapa banyak angka yang memiliki posisi kemunculan yang lebih besar dari posisi kemunculan data disamping kanannya. Setelah itu, tambahkan $1$ pada jawaban.

## Proof of Correctness

> [!TIP]
> Kenapa array harus menampung tipe data berpasangan?

Array harus menampung tipe data berpasangan (seperti `pair<int, int>` dalam C++) karena kita perlu menjaga relasi antara nilai angka itu sendiri dengan posisi indeks aslinya sebelum array tersebut diurutkan.

Ketika kita melakukan sorting secara *ascending* berdasarkan nilai angkanya, posisi atau urutan asli elemen-elemen tersebut di dalam array awal akan hilang atau berubah.

Dengan menyertakan indeks aslinya sebagai pasangan, kita bisa dengan mudah melacak dan membandingkan apakah suatu angka (misalnya angka $x$) muncul lebih dulu atau lebih belakangan dibandingkan angka berikutnya ($x + 1$) pada susunan awal, yang menjadi inti dari aturan perpindahan ronde pada soal Collecting Numbers.

> [!TIP]
> Kenapa solusi dari masalah ini adalah cukup menghitung banyaknya data yang memiliki posisi lebih besar dari posisi data di sebelah kananya, atau $data[i].pos > data[i+1].pos$?

Kita menghitung kondisi $data[i].pos > data[i+1].pos$ karena proses pengumpulan angka dalam soal ini dilakukan secara berurutan mulai dari $1, 2, 3, \dots, n$ dalam satu putaran penuh dari kiri ke kanan.

Ketika array sudah diurutkan secara ascending berdasarkan nilainya, kita sedang meninjau urutan bilangan yang seharusnya kita kumpulkan secara ideal.

Jika posisi indeks suatu angka lebih besar daripada posisi indeks angka berikutnya ($data[i].pos > data[i+1].pos$), artinya pada susunan asli array tersebut, angka yang lebih besar justru muncul lebih dulu daripada angka yang lebih kecil.

Kondisi "mundur" atau "melompat ke kiri" ini menandakan bahwa kita tidak bisa mengumpulkan kedua angka tersebut dalam satu putaran yang sama secara beruntun, sehingga kita terpaksa harus menyelesaikan satu putaran penuh terlebih dahulu dan memulai putaran (ronde) baru.

> [!TIP]
> Kenapa pemeriksaan hanya dilakukan sebatas dua elemen berpasangan saja setelah disorting? Tidak dengan elemen lain sekaligus?

Setelah array diurutkan secara ascending berdasarkan nilainya, elemen-elemen yang saling berurutan secara matematis (seperti $x$ dan $x + 1$) akan diletakkan tepat berdampingan atau berdekatan satu sama lain.

Kita tidak perlu membandingkan elemen yang letaknya berjauhan secara sekaligus karena aturan inti dari permainan ini adalah menghitung perpindahan putaran yang dipicu oleh **kegagalan urutan kemunculan antar angka yang bernilai konsekutif (berurutan)**, yaitu angka $k$ dan $k+1$.

Jika angka $k+1$ muncul lebih dulu daripada angka $k$ pada array asli ($data[i].pos > data[i+1].pos$), itu sudah menjadi bukti mutlak bahwa keduanya tidak bisa diselesaikan dalam satu putaran yang sama, sehingga cukup pasangan bertetangga ini saja yang mendikte kapan ronde baru wajib dimulai.

> [!TIP]
> Kenapa penambahan $1$ pada jawaban akhir diperlukan?

Penambahan $1$ pada jawaban akhir diperlukan karena variabel *counter* yang kita gunakan di dalam perulangan hanya bertugas menghitung **berapa kali terjadi perpindahan putaran** atau berapa kali kita terpaksa melompat mundur ke ronde baru.

Setiap kali kondisi $data[i].pos > data[i+1].pos$ terpenuhi, itu merepresentasikan jumlah "sisipan" atau tambahan ronde yang dibutuhkan setelah ronde pertama.

Ronde atau putaran awal yang pasti selalu dikerjakan sejak awal tidak terhitung oleh kondisi tersebut, sehingga kita wajib menambahkan $1$ di akhir untuk merepresentasikan putaran pertama yang mutlak ada.

## Code Implementation

```cpp
#include <bits/stdc++.h>

#ifdef LOCAL
#include "schematics.hpp"
static_assert(schematics::invariant);
#else
#define debug(...)
#endif

using namespace std;

void solve() {
    int n;
    cin >> n;
    vector<pair<int, int>> vec(n);
    for (int i = 0; i < n; i++) {
        cin >> vec[i].first;
        vec[i].second = i;
    }

    sort(vec.begin(), vec.end());
    int cnt = 1;
    for (int i = 0; i < n - 1; i++) {
        cnt += vec[i].second > vec[i + 1].second;
    }

    cout << cnt;
}

auto main() -> int {
    std::ios_base::sync_with_stdio(false);
    std::cin.tie(nullptr);
    int t = 1;
    // cin >> t;
    while (t--) {
        solve();
    }
    return 0;
}
```
