# Minimizing Coins

![](2.%20Minimizing%20Coins-1.png)

## Problem

Pertimbangkan sebuah sistem mata uang yang terdiri dari $n$ koin. Setiap koin memiliki nilai bilangan bulat positif. Tugas Anda adalah menghasilkan jumlah uang $x$ menggunakan koin-koin yang tersedia sedemikian rupa sehingga jumlah koin yang digunakan minimal.

Sebagai contoh, jika koin yang tersedia adalah $\{1,5,7\}$ dan jumlah yang diinginkan adalah $11$, solusi optimalnya adalah $5+5+1$ yang membutuhkan $3$ koin.

## Solution
Persoalan Minimizing Coins di CSES adalah variasi klasik dari *Unbounded Knapsack* atau *Coin Change Problem*. Berbeda dengan Dice Combinations yang menghitung **banyaknya cara**, di sini kita diminta mencari **jumlah koin minimum** untuk membentuk total nilai $x$ dari daftar nilai koin yang diberikan.

### 1. Memahami Inti Masalah

Diberikan $n$ jenis koin dengan nilai tertentu $c = \{c_1, c_2, \dots, c_n\}$ dan sebuah nilai target $x$. Kita bisa menggunakan setiap jenis koin sebanyak yang kita mau. Tujuannya adalah mencari jumlah koin paling sedikit agar total nilainya tepat sama dengan $x$. Jika nilai $x$ tidak memungkinkan untuk dibentuk dari koin yang ada, kembalikan $-1$.

### 2. Formulasi State DP

* **Definisi State:** $dp[i]$ = jumlah koin minimum yang dibutuhkan untuk membentuk total nilai $i$.
* **Target:** Kita ingin mencari nilai dari $dp[x]$.

### 3. Base Case & Inisialisasi

* **Base Case:** $dp[0] = 0$. Untuk membuat nilai total 0, kita membutuhkan tepat 0 koin.
* **Inisialisasi Nilai Awal:** Semua elemen array $dp[1 \dots x]$ perlu diisi dengan sebuah nilai sentinel yang sangat besar, misal $\infty$ (atau nilai yang cukup besar melebihi batas jawaban, seperti $10^9$). Ini mewakili kondisi awal di mana target nilai tersebut belum/tidak bisa dibentuk.

### 4. Transisi DP (Relasi Rekurens)

Untuk mencari jumlah koin minimum untuk membentuk nilai $i$, bayangkan koin terakhir yang kita gunakan. Jika kita menggunakan koin bernilai $c_j$, maka nilai yang tersisa sebelum koin tersebut ditambahkan adalah $i - c_j$.

Banyaknya koin yang dibutuhkan dari pilihan koin $c_j$ tersebut adalah jumlah koin untuk nilai sisa ditambah 1 koin yang baru saja kita pakai, yaitu $dp[i - c_j] + 1$.

Karena kita ingin mencari **jumlah koin paling sedikit**, kita harus memilih nilai terkecil di antara seluruh jenis koin yang tersedia:

$$dp[i] = \min_{j=1}^{n} (dp[i - c_j] + 1) \quad \text{untuk setiap } c_j \le i$$


### 5. Strategi Penyelesaian (Bottom-Up)

1. **Inisialisasi Array:** Buat array $dp$ berukuran $x + 1$. Set $dp[0] = 0$ dan seluruh elemen dari $dp[1]$ hingga $dp[x]$ dengan nilai $10^9$.
2. **Iterasi Target ($i$):** Jalankan perulangan luar dari $i = 1$ sampai $x$ untuk menyelesaikan masalah secara bertahap dari nilai terkecil.
3. **Iterasi Jenis Koin ($c_j$):** Di dalam perulangan luar, periksa setiap jenis koin $c_j$ yang ada di daftar input.
4. **Update State:** Jika $i - c_j \ge 0$, atau $i \ge c_j$, perbarui nilai $dp[i]$ dengan nilai minimum antara $dp[i]$ saat ini dan $dp[i - c_j] + 1$.
5. **Cek Hasil Akhir:** Setelah seluruh perulangan selesai, periksa nilai $dp[x]$. Jika nilai $dp[x]$ masih berupa nilai inisialisasi awal ($10^9$), artinya nilai $x$ tidak bisa dibentuk, maka cetak `-1`. Jika tidak, cetak nilai $dp[x]$.
### Mengapa Urutan Loop Luar Memilih Target $i$?

Karena di masalah ini koin yang sama bisa digunakan berulang kali dan urutan pengambilan koin tidak relevan terhadap jumlah koin yang dipakai (misal: memakai koin 2 lalu 5 sama-sama membutuhkan 2 koin dengan memakai koin 5 lalu 2), struktur perulangan di mana target $i$ berada di luar dan jenis koin di dalam sudah cukup untuk mengeksplorasi seluruh kombinasi secara optimal.

Kompleksitas waktu dari pendekatan ini adalah $O(x \cdot n)$, di mana $x$ adalah target nilai dan $n$ adalah banyaknya jenis koin.
## Proof of Correctness
### PoC 1

> [!TIP]
> Kenapa formula...
> $$dp[i] = \min_{j=1}^{n} (dp[i - c_j] + 1) \quad \text{untuk setiap } c_j \le i$$ 
> harus menggunakan $+ 1$ pada bagian $dp[i - c_j]$?


Operasi $+ 1$ pada formula tersebut mewakili **penambahan tepat satu buah koin** yang baru saja dipilih ke dalam susunan koin yang sudah ada.

Tinjau relasi transisinya secara mendasar. Nilai $dp[i - c_j]$ menyatakan jumlah koin minimum yang dibutuhkan untuk membentuk total nilai sebesar $i - c_j$. Ketika kita memutuskan untuk mengambil satu koin bernilai $c_j$ demi mencukupi sisa target agar menjadi $i$, total nilai yang terbentuk bertambah sebesar $c_j$, sedangkan **banyaknya koin yang dipakai bertambah sebanyak 1 buah**.

Jika ditinjau dari prinsip induksi matematika dan bukti optimalitas (*Optimal Substructure*):

Setiap kombinasi koin yang menghasilkan nilai total $i$ pasti memiliki setidaknya satu koin terakhir, katakanlah koin bernilai $c_j$. Jika kombinasi koin untuk nilai $i$ tersebut adalah kombinasi dengan jumlah koin paling sedikit (optimal), maka sisa koin setelah koin $c_j$ dikeluarkan haruslah merupakan kombinasi koin optimal untuk membentuk nilai $i - c_j$.

Jika jumlah koin optimal untuk membentuk nilai $i - c_j$ dinotasikan sebagai $dp[i - c_j]$, maka dengan memasukkan kembali satu koin $c_j$ yang sempat dikeluarkan tadi, total koin yang dibutuhkan secara mutlak adalah $dp[i - c_j] + 1$.

Tanpa adanya penambahan $+ 1$, algoritma hanya akan menyalin jumlah koin dari sisa nilai $i - c_j$ tanpa pernah memperhitungkan koin $c_j$ itu sendiri, sehingga nilai $dp[i]$ tidak akan pernah bertambah dari $dp[0] = 0$.

### PoC 2

> [!TIP]
> Melihat bagaimana algoritma berjalan dalam array $dp$, artinya akan ada banyak celah-celah pada array tersebut yang tidak bisa disusun dengan koin yang tersedia, sehingga akan ada banyak elemen pada array $dp$ yang tetap $10^9$?

Tepat sekali. Elemen-elemen array $dp$ yang nilainya tetap $10^9$ hingga akhir eksekusi mewakili nilai-nilai target $i$ yang **tidak mungkin dibentuk** oleh kombinasi nominal koin yang tersedia.

Sebagai ilustrasi sederhana, bayangkan kamu hanya memiliki koin dengan nominal $3$ dan $5$, lalu ingin membentuk berbagai nilai target dari $1$ hingga $10$:

* $dp[0] = 0$ (base case).
* $dp[1]$ dan $dp[2]$ akan bernilai $10^9$ karena tidak ada koin $\le 1$ atau $\le 2$.
* $dp[3] = dp[0] + 1 = 1$.
* $dp[4]$ bernilai $10^9$ karena $4 - 3 = 1$ ($dp[1] = 10^9$) dan $4 - 5 < 0$.
* $dp[5] = dp[0] + 1 = 1$.
* $dp[6] = dp[3] + 1 = 2$.
* $dp[7]$ bernilai $10^9$ karena $7 - 3 = 4$ ($dp[4] = 10^9$) dan $7 - 5 = 2$ ($dp[2] = 10^9$).
* $dp[8] = dp[5] + 1 = 2$
* $dp[9]=dp[6]+1=3$
* $dp[10]=dp[5]+1=2$

Keberadaan nilai sentinel $10^9$ ini berfungsi mencegah nilai yang tidak valid ikut dalam perhitungan nilai yang lebih besar. Jika $dp[i - c_j]$ bernilai $10^9$, maka operasi $dp[i - c_j] + 1$ akan menghasilkan $10^9 + 1$, yang mana tidak akan pernah terpilih oleh fungsi $\min()$ selama ada opsi kombinasi valid lain yang bernilai jauh lebih kecil.

Celah-celah tak terjangkau ini merupakan sifat alami dari problem kombinasi koin. Jika koin yang tersedia tidak bisa membentuk nilai tertentu, celah tersebut akan tetap bernilai $10^9$ hingga program selesai.
## Code Implementation

```cpp
#include <algorithm>
#include <iostream>
#include <vector>
using namespace std;

auto main() -> int {
    int n, x;
    cin >> n >> x;
    vector<int> coins(n);
    for (auto& a : coins) {
        cin >> a;
    }

    vector<int> dp(x + 1, 1e9);
    dp[0] = 0;

    for (int i = 1; i <= x; i++) {
        for (int j = 0; j < n; j++) {
            if (i - coins[j] >= 0) {
                dp[i] = min(dp[i - coins[j]] + 1, dp[i]);
            }
        }
    }

    if (dp[x] == 1e9) {
        cout << -1;
    } else {
        cout << dp[x];
    }

    return 0;
}
```
