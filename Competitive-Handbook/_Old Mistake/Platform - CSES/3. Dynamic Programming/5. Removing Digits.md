# Removing Digits

![](5.%20Removing%20Digits-1.png)

## Problem

Anda diberikan sebuah bilangan bulat $n$. Pada setiap langkah, Anda dapat mengurangkan salah satu digit dari bilangan tersebut.

Berapa banyak langkah yang diperlukan untuk membuat bilangan tersebut menjadi $0$?

## Solution

Persoalan **Removing Digits** di CSES membawa variasi baru di mana pilihan transisinya tidak lagi statis dari input koin atau dadu, melainkan **dinamis berdasarkan digit-digit** dari angka itu sendiri.

### 1. Memahami Inti Masalah

Diberikan sebuah bilangan bulat $n$. Dalam satu langkah, kamu diperbolehkan mengurangkan $n$ dengan salah satu digit yang ada pada bilangan $n$ tersebut (selain angka 0). Tujuannya adalah mencari **jumlah langkah minimum** untuk mengubah nilai $n$ menjadi $0$.

Sebagai contoh, jika $n = 27$, digit yang tersedia adalah 2 dan 7.

* Jika kita pilih 7: $27 - 7 = 20$.
* Dari 20, digit selain nol yang ada adalah 2: $20 - 2 = 18$.
* Dan seterusnya hingga mencapai 0.

### 2. Formulasi State DP

* **Definisi State:** $dp[i]$ = jumlah langkah minimum untuk mengurangi nilai $i$ menjadi $0$.
* **Target:** Mencari nilai dari $dp[n]$.

### 3. Base Case & Inisialisasi

* **Base Case:** $dp[0] = 0$. Nilai 0 membutuhkan tepat 0 langkah untuk menjadi 0.
* **Inisialisasi:** Semua elemen $dp[1 \dots n]$ diisi dengan nilai sentinel yang besar, misalnya $\infty$ (atau $10^9$).

### 4. Transisi DP (Relasi Rekurens)

Untuk sebuah nilai $i$, kita perlu memeriksa semua digit yang membentuk nilai $i$ tersebut. Sebut himpunan digit dari $i$ sebagai $D(i)$.

Jika kita memilih untuk mengurangkan $i$ dengan salah satu digit $d \in D(i)$ (dengan $d > 0$), maka nilai sisa setelah pengurangan adalah $i - d$.

Banyaknya langkah yang dibutuhkan adalah langkah untuk nilai sisa $i - d$ ditambah $1$ langkah yang baru saja dilakukan. Karena kita ingin meminimalkan jumlah langkah:

$$dp[i] = \min_{d \in D(i), d > 0} (dp[i - d] + 1)$$

### 5. Strategi Penyelesaian (Bottom-Up)

1. **Inisialisasi Array:** Buat array $dp$ berukuran $n + 1$, set $dp[0] = 0$, dan $dp[1 \dots n] = 10^9$.
2. **Iterasi Nilai Target ($i$):** Perulangan luar berjalan dari $i = 1$ sampai $n$.
3. **Eksplorasi Digit:** Untuk nilai $i$ saat ini, ekstrak semua digitnya menggunakan operasi aritmatika (seperti `temp = i`, `digit = temp % 10`, `temp /= 10`).
4. **Update State:** Untuk setiap digit $d > 0$ yang ditemukan dari $i$, perbarui nilai $dp[i]$:

$$dp[i] = \min(dp[i], dp[i - d] + 1)$$


5. **Output:** Cetak nilai $dp[n]$.

### Catatan Menarik (Greedy vs DP)

Meskipun persoalan ini dirancang untuk latihan DP dengan kompleksitas $O(n \cdot \text{jumlah digit})$, masalah ini sebenarnya juga bisa diselesaikan menggunakan pendekatan **Greedy**: pada setiap langkah, selalu pilih **digit terbesar** yang ada pada nilai $i$. Pendekatan Greedy ini terbukti selalu optimal untuk kasus pengurangan digit dan berjalan jauh lebih cepat. Namun, menyelesaikannya dengan DP adalah cara yang sangat bagus untuk memahami bagaimana state terbentuk dari sifat dinamis angka itu sendiri.
## Proof of Correctness
### PoC 1

> [!TIP]
> Kenapa pendekatan *dynamic programming* bisa digunakan disini walaupun *greedy* juga bisa?


Diberikan sebuah bilangan bulat $n \ge 0$. Didefinisikan $D(i)$ sebagai himpunan digit-digit yang menyusun bilangan $i$. Untuk setiap $i > 0$, himpunan langkah transisi yang valid didefinisikan sebagai $T(i) = \{ i - d \mid d \in D(i), d > 0 \}$.

Pendekatan Dynamic Programming terbukti valid dan dijamin selalu memberikan solusi optimal karena masalah ini memenuhi dua syarat utama DP: **Optimal Substructure** dan **Overlapping Subproblems**.

Pertama, mengenai **Optimal Substructure** (Struktur Sub-masalah Optimal).
Misalkan jalur pengurangan optimal dari $i$ menuju $0$ membutuhkan $k$ langkah, dengan langkah pertama mengurangkan $i$ dengan digit $d^* \in D(i)$ menuju nilai sisa $i - d^*$. Maka, jalur sisa dari $i - d^*$ menuju $0$ haruslah merupakan jalur pengurangan optimal untuk $i - d^*$ yang membutuhkan tepat $k - 1$ langkah.

Jika terdapat jalur lain dari $i - d^*$ menuju $0$ yang membutuhkan kurang dari $k - 1$ langkah (misalnya $m < k - 1$), maka kita bisa memilih jalur tersebut untuk membuat total langkah dari $i$ menjadi $1 + m < k$. Hal ini kontradiksi dengan asumsi bahwa $k$ adalah jumlah langkah minimum dari $i$. Jadi, solusi optimal untuk $i$ dibangun secara langsung dari solusi optimal untuk $i - d^*$.

Secara induksi matematika kuat (*Strong Induction*):

1. **Base Case:** Untuk $i = 0$, $dp[0] = 0$. Jelas benar karena 0 tidak memerlukan langkah pengurangan.
2. **Induction Step:** Asumsikan untuk semua $k < i$, nilai $dp[k]$ secara tepat menyimpan jumlah langkah minimum menuju $0$. Untuk nilai $i$, kita mengeksplorasi seluruh kemungkinan transisi $i - d$ di mana $d \in D(i)$ dan $d > 0$. Karena $d > 0$, maka selalu berlaku $i - d < i$. Berdasarkan hipotesis induksi, nilai $dp[i - d]$ untuk seluruh sisa nilai tersebut sudah optimal. Mengambil nilai terkecil di antara seluruh pilihan transisi yang ada:

$$dp[i] = \min_{d \in D(i), d > 0} (dp[i - d] + 1)$$

dijamin menghasilkan jumlah langkah minimum yang sah untuk $i$.

Kedua, mengenai **Overlapping Subproblems** (Sub-masalah yang Tumpang Nindih).
Banyak nilai $i$ yang berbeda dapat bertransisi ke nilai sisa yang sama. Sebagai contoh, dari nilai $27$ (jika dikurangi $7$) dan nilai $22$ (jika dikurangi $2$), keduanya akan mencapai sub-masalah yang sama, yaitu nilai $20$. DP menyimpan nilai optimal $dp[20]$ dalam memori sehingga perhitungan untuk nilai $20$ hanya dilakukan tepat satu kali.

Kesimpulannya, walaupun pendekatan Greedy bisa digunakan karena ada sifat khusus di mana memilih digit terbesar $d^* = \max(D(i))$ selalu optimal, pendekatan DP tetap valid secara mutlak. DP mengeksplorasi seluruh ruang transisi yang mungkin ($d \in D(i)$) dan memilih yang minimum, sehingga solusi optimal dijamin selalu ditemukan tanpa perlu membuktikan sifat greedy-nya terlebih dahulu.

## Code Implementation

### Pendekatan *greedy*

Dengan mengambil hanya digit terbesar sebagai pengurang $n$, maka akan selalu didapat solusi optimal:

```cpp
#include <algorithm>
#include <iostream>
using namespace std;

auto main() -> int {
    int n, cnt = 0;
    cin >> n;

    while (n > 0) {
        int dig = 0;
        int temp = n;

        while (temp > 0) {
            dig = max(dig, temp % 10);
            temp /= 10;
        }

        n -= dig;
        cnt++;
    }

    cout << cnt;
    return 0;
}
```

Dengan menggunakan pendekatan *dynamic programing*, seperti cara yang soal ini ingin kita gunakan:

```cpp
#include <iostream>
#include <vector>
using namespace std;

auto main() -> int {
    int n;
    cin >> n;

    vector<int> dp(n + 1, 1e9);
    dp[0] = 0;

    for (int i = 1; i <= n; i++) {
        int temp = i;
        while (temp > 0) {
            dp[i] = min(dp[i], dp[i - (temp % 10)] + 1);
            temp = temp / 10;
        }
    }

    cout << dp[n];

    return 0;
}
```
