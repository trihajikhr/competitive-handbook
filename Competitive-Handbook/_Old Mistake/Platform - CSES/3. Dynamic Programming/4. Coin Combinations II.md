# Coin Combinations II

![](4.%20Coin%20Combinations%20II-1.png)

## Problem

Pertimbangkan sebuah sistem mata uang yang terdiri dari $n$ koin. Setiap koin memiliki nilai bilangan bulat positif. Tugas Anda adalah menghitung banyaknya cara urut berbeda (*distinct ordered ways*) untuk menghasilkan jumlah uang $x$ menggunakan koin-koin yang tersedia.

Sebagai contoh, jika koin yang tersedia adalah $\{2,3,5\}$ dan jumlah yang diinginkan adalah $9$, terdapat $3$ cara:

* $2+2+5$
* $3+3+3$
* $2+2+2+3$

## Solution

Jika pada Coin Combinations I kita menghitung banyaknya urutan (permutasi), maka pada **Coin Combinations II** kita diminta menghitung **banyaknya kombinasi unik** di mana **urutan koin tidak berpengaruh**. Sebagai contoh, susunan $(2, 5)$ dan $(5, 2)$ dianggap sebagai **1 kombinasi yang sama**.

### 1. Memahami Inti Masalah

Diberikan $n$ jenis koin $c = \{c_1, c_2, \dots, c_n\}$ dan target nilai $x$. Kamu diminta mencari banyaknya kombinasi koin yang bernilai total $x$. Karena urutan tidak diperhitungkan, kita harus mencegah terjadinya penghitungan ganda (*double counting*).

### 2. Formulasi State DP

* **Definisi State:** $dp[i]$ = banyaknya kombinasi unik untuk membentuk total nilai $i$.
* **Target:** Mencari nilai dari $dp[x]$.

### 3. Base Case & Inisialisasi

* $dp[0] = 1$: Ada tepat 1 cara untuk membentuk nilai 0, yaitu dengan tidak memilih koin sama sekali.
* Seluruh elemen $dp[1 \dots x]$ diinisialisasi dengan $0$.

### 4. Transisi DP & Kunci Penyelesaian

Secara matematis, persamaan penambahannya tetap sama dengan Coin Combinations I:

$$dp[i] = dp[i] + dp[i - c_j]$$

Namun, kunci utama agar urutan koin tidak diperhitungkan (tidak ada *double counting*) terletak pada **urutan perulangannya (*loop order*)**.

Kita harus memproses koin satu per satu secara global. Artinya, selesaikan seluruh pembentukan nilai $i$ menggunakan koin $c_1$ terlebih dahulu, baru kemudian perbarui array menggunakan koin $c_2$, lalu $c_3$, dan seterusnya.

Dengan memaksa algoritma memproses koin dari $c_1$ hingga $c_n$, kita secara tidak langsung memaksakan bahwa koin dalam setiap kombinasi dipasang dengan urutan yang tidak pernah mengecil (*non-decreasing order*). Akibatnya, kombinasi seperti $(5, 2)$ tidak akan pernah terbentuk jika $(2, 5)$ sudah dihitung.

### 5. Strategi Penyelesaian (Bottom-Up)

1. **Inisialisasi Array:** Buat array $dp$ berukuran $x + 1$ diisi nilai $0$, lalu set $dp[0] = 1$.
2. **Iterasi Jenis Koin ($c_j$) - OUTER LOOP:** Perulangan luar berjalan melewati setiap koin dari $j = 0$ sampai $n - 1$.
3. **Iterasi Target ($i$) - INNER LOOP:** Perulangan dalam berjalan dari $i = c_j$ sampai $x$.
4. **Update State:** Tambahkan nilai $dp[i - c_j]$ ke $dp[i]$.
5. **Aritmatika Modulo:** Lakukan modulo $10^9 + 7$ pada setiap penjumlahan.

### Ringkasan Perbedaan Coin Combinations I vs II

* **Coin Combinations I (Permutasi / Urutan Berpengaruh):**
Perulangan target $i$ di luar, perulangan koin $c_j$ di dalam. Setiap posisi $i$ bebas memilih koin apa saja di langkah terakhir.
* **Coin Combinations II (Kombinasi / Urutan Tidak Berpengaruh):**
Perulangan koin $c_j$ di luar, perulangan target $i$ di dalam. Array $dp$ diperbarui koin demi koin secara bertahap.
## Proof of Correctness
### PoC 1

> [!TIP]
> Kenapa solusi ini bisa menghitung banyaknya kombinasi dengan tepat?


Diberikan $n$ jenis koin $c_1, c_2, \dots, c_n$ yang diurutkan secara tetap. Setiap kombinasi unik dari koin-koin yang bernilai total $i$ dapat didefinisikan sebagai sebuah tuple $(k_1, k_2, \dots, k_n)$, di mana $k_j \ge 0$ menyatakan banyaknya koin jenis $c_j$ yang digunakan, sedemikian rupa sehingga:

$$\sum_{j=1}^{n} k_j \cdot c_j = i$$

Bentuk tuple ini secara alami menghilangkan faktor urutan. Kombinasi 2 koin bernilai 2 dan 1 koin bernilai 5 akan selalu terwakili oleh tuple yang sama, yaitu $(2, 1)$, tidak peduli apakah koin tersebut diambil dengan urutan $(2, 2, 5)$, $(2, 5, 2)$, atau $(5, 2, 2)$.

Menggunakan Induksi Matematika, kita buktikan bahwa setelah perulangan luar (*outer loop*) selesai memproses koin ke-$k$ (yaitu koin $c_k$), elemen $dp[i]$ secara tepat menyimpan banyaknya tuple $(k_1, k_2, \dots, k_k)$ yang memenuhi:

$$\sum_{j=1}^{k} k_j \cdot c_j = i$$

Untuk kasus dasar $k = 0$ (sebelum ada koin yang diproses), $dp[0] = 1$ dan $dp[i] = 0$ untuk $i > 0$. Ini benar karena tanpa koin sama sekali, hanya nilai 0 yang dapat dibentuk dengan 1 cara (tuple kosong).

Sebagai hipotesis induksi, asumsikan bahwa setelah memproses koin ke-$(k-1)$, array $dp[i]$ sudah secara tepat menyimpan banyaknya kombinasi unik yang **hanya menggunakan subset koin** $\{c_1, c_2, \dots, c_{k-1}\}$.

Pada langkah induksi untuk koin ke-$k$ ($c_k$), perulangan dalam (*inner loop*) berjalan naik dari $i = c_k$ sampai $x$ dengan melakukan transisi:

$$dp[i] = dp[i] + dp[i - c_k]$$

Nilai $dp[i]$ di sisi kanan mewakili banyaknya kombinasi membentuk nilai $i$ tanpa menggunakan koin $c_k$ sama sekali (yaitu $k_k = 0$). Nilai $dp[i - c_k]$ mewakili banyaknya kombinasi membentuk nilai $i$ yang menggunakan **setidaknya satu** koin $c_k$ (yaitu $k_k \ge 1$).

Karena perulangan dalam berjalan dari $i = c_k$ ke atas (meningkat), nilai $dp[i - c_k]$ yang dibaca sudah mencakup pembaruan dari koin $c_k$ itu sendiri. Ini secara rekursif memungkinkan koin $c_k$ digunakan sebanyak 1, 2, 3, atau lebih ($k_k \ge 1$) secara tepat tanpa ada yang terlewat.

Kedua himpunan kombinasi ini (kombinasi dengan $k_k = 0$ dan kombinasi dengan $k_k \ge 1$) bersifat saling lepas (*disjoint*). Menurut Aturan Penjumlahan (*Sum Rule*), menjumlahkannya memberikan total kombinasi unik yang valid untuk nilai $i$ menggunakan koin $\{c_1, \dots, c_k\}$.

Karena setiap koin $c_1, \dots, c_n$ diproses tepat satu kali secara bertahap dari awal hingga akhir, hasil akhirnya pada $dp[x]$ dijamin mencakup seluruh tuple $(k_1, k_2, \dots, k_n)$ yang valid tanpa ada satu pun kombinasi yang terhitung dua kali.

### PoC 2
> [!TIP]
> Jadi bentuk kombinasi yang didapat, akan selalu memulai dari koin dari indeks pertama, dan bergerak ke indeks terakhir, dan mustahil terbalik secara urutan?

Tepat sekali. Pemahamanmu sangat tajam.

Secara teknis, algoritma ini memaksakan sebuah aturan ketat yang disebut **Canonical Representation** (Representasi Kanonis).

Karena perulangan koin bergerak secara bertahap dari $c_1 \to c_2 \to \dots \to c_n$, setiap kombinasi yang valid **dipaksa** untuk dicatat hanya dalam satu urutan indeks yang monoton naik (non-decreasing index).

Sebagai contoh, jika kamu memiliki koin $\{2, 3, 5\}$ dan target nilai $7$:

Kombinasi $2 + 5$ akan dicatat sebagai urutan indeks $(1, 3)$.
Urutan ini valid karena indeks koinnya naik ($1 \le 3$). Saat perulangan berada di koin 2, nilai $dp[2]$ terbentuk. Kemudian saat perulangan sampai di koin 5, nilai $dp[7]$ diperbarui dengan menambah $dp[7 - 5]$ (yaitu $dp[2]$).

Sebaliknya, kombinasi $5 + 2$ membutuhkan urutan indeks $(3, 1)$.
Urutan ini **secara struktur tidak mungkin terjadi** dalam perulangan. Ketika algoritma sedang memproses koin 5 (indeks 3), ia membutuhkan nilai $dp[5 - 2] = dp[3]$ dari koin 2 (indeks 1). Namun, koin 2 sudah selesai diproses jauh di awal dan perulangan outer untuk koin 2 tidak akan pernah dipanggil ulang.

Artinya, urutan terbalik $(3, 1)$ dianggap tidak ada karena pintunya sudah tertutup.

Dengan mengunci urutan pembentukan agar selalu searah dari indeks pertama ke indeks terakhir, setiap kombinasi unik hanya memiliki **tepat satu jalur pembentukan yang sah**. Inilah alasan utama mengapa *double counting* tereliminasi sepenuhnya secara sistematis.

## Code Implementation

```cpp
#include <iostream>
#include <vector>
using namespace std;

constexpr int M = 1e9 + 7;

auto main() -> int {
    int n, x;
    cin >> n >> x;
    vector<int> c(n);
    for (int i = 0; i < n; i++) {
        cin >> c[i];
    }

    vector<int> dp(x + 1, 0);
    dp[0] = 1;

    for (int i = 0; i < n; i++) {
        for (int j = c[i]; j <= x; j++) {
            dp[j] = (dp[j] + dp[j - c[i]]) % M;
        }
    }

    cout << dp[x];
    return 0;
}
```
